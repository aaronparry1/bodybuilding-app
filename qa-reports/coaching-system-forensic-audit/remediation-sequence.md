# Dependency-ordered remediation sequence

No remediation was implemented by this audit.

## Phase 0 — protect what works

1. Freeze the current atomic onboarding commit, carrier persistence, immutable v3 snapshots, Train ledger/idempotency/discard behavior, exact-target editing and method fail-closed tests.
2. Add a production-reachability test that starts at mounted Progress and proves the intended chain before any activation.
3. Preserve recorded history byte-for-byte through every later revision.

## P0 — close the longitudinal loop

1. **Define actual evidence interpretation.** Derive comparable completion, target achievement, stalls, drop-off, recovery and pain from factual ledger/readiness inputs. Do not accept caller-authored transition booleans as evidence.
2. **Repair construction facts.** Use exercise-scoped load evidence; retain typed limitations, learned preferences and relevant history; fail closed when facts are stale or absent.
3. **Mount decision production.** Persist evidence → evaluation → bounded intervention → decision with deterministic identities and stale/conflict rejection.
4. **Apply through the existing canonical owner.** Use `canonicalActivePlanState.applyProgressDecision`, CAS revision and future Session Construction only.
5. **Certify 12–16-week behavior.** Require material differences for high response, stall, poor recovery, missed sessions, pain, return from layoff and event approach.

## P1 — make personalization real

1. Add factual equipment intake; do not assume full gym.
2. Add typed limitation capture and safe update semantics.
3. Add suitability-preserving Train substitution and a bounded learned-preference record.
4. Mount missed-session reflow and recovery review without inventing automatic deload/load changes.
5. Add plain-language reason projection for every persisted decision.

## P2 — isolate conflicting surfaces

1. Prove callers/deep links for legacy builder/session routes.
2. Remove or explicitly quarantine them; do not adapt their legacy repository into canonical authority.
3. Preserve event type if it has a real Macrocycle decision; otherwise remove the redundant question.
4. Repair/replace the corrupt source file only through a source-management task.

## P3 — breadth only after coherence

1. Consider additional methods only with phase, evidence, exact execution, progression, stop and exit contracts.
2. Expand body-metric and sport context only where it changes an approved owner.
3. Add method variety only when it serves a named adaptation—not novelty.

## Acceptance gate

The app may be described as autoregulated only after:

- mounted route proof exists;
- all P0 defects are closed;
- at least the 12 required scenarios show appropriate distinct decisions;
- identical input is deterministic;
- every changed snapshot has a persisted reason/evidence chain;
- no unsupported numeric load mutation is introduced;
- Home, Plan, Train and Progress show the same new revision.
