# Pre-exercise prescription-slot source audit

| Current input / output | Source | Pre-selection status | D2.5 treatment |
| --- | --- | --- | --- |
| goal, days, split, experience | `plan-setup.ts` | persisted planning input | policy input |
| current mesocycle/microcycle/session role | `current-planning-input.ts`, current microcycle | current planning intent | policy input |
| generated set guidance/settings | generator, presets, slot matrix, `withSetPrescription` | post-selection constructor output | decomposed; never identity source |
| exercise identity/equipment/history/intervention | library/selection/replacement paths | selection stage | selection constraints/result, not slot identity |
| exact targets | planned workout construction | post-construction executable authority | excluded |

The policy source must answer ordered training jobs before selection. Candidate slot domains: muscle, movement pattern and exercise-slot role. Generated output cannot be promoted to persisted authority because it is recreated and may reorder/select substitutes.

Current microcycle priority is provisionally a construction projection unless it changes full-microcycle programme structure; mesocycle purpose controls programme policy. Equipment usually constrains selection rather than deleting jobs. New policy must return explicit unsupported combinations rather than falling back to generated settings.

Owner decisions: direct per-session guidance versus an allocation layer; exact taxonomy; beginner/intermediate differences; body-part and Bench-Squat-Deadlift roles; weak-point and optional accessory policy; equipment substitution; initial goal/purpose coverage. Recommended initial rollout is hypertrophy-only direct slot guidance, then explicit strength/power coverage.
