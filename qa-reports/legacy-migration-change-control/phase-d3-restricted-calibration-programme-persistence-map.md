# Restricted D3 calibration programme persistence map

## Scope

This phase persists immutable programme metadata only for newly created intermediate, four-day, full-gym Upper/Lower `hypertrophy_calibration` plans. Existing generated exercise settings remain the session-construction authority until D4.

## Stable allocation

For supported new plans, D3 allocates one programme ID, four template IDs in `upper-a`, `lower-a`, `upper-b`, `lower-b` order, and one slot ID per resolved policy definition. Compatibility plans consume none of these IDs. IDs are never generated by policy or hydration.

## Authority boundary

`programmeSpecifications` are immutable persisted planning metadata. No slot mutation API, adjustment writer, session-construction reader, generated-setting synchronization, or UI authority is introduced. D4 is the explicit construction read-authority migration gate.
