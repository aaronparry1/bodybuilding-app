# Discard lifecycle contract

Verdict: **PROVEN**

The existing product contract is preservation by restoration:

1. The user explicitly opens a destructive confirmation.
2. Cancellation performs no persistence command.
3. Confirmation persists a durable intent.
4. The mutable active attempt is removed.
5. The exact immutable prescription snapshot is restored once as the same planned-session identity.
6. Active references, performed-work evidence, and the rest timer are removed.
7. Completed historical sessions remain immutable.
8. Home and Plan expose the restored session as planned; the discarded recorded-session Train projection is unavailable.
9. A later start creates a clean attempt for the same planned session.

Discard does not mark completed work, missed work, adherence, PRs, trends, progression, or regression. It neither creates a replacement prescription nor changes programme structure.

The durable intent allows these restart outcomes:

- pre-CAS: restore exact ledger and retry safely;
- post-CAS/pre-cleanup: finish cleanup without reapplying the carrier revision;
- already complete: return an idempotent result;
- changed/conflicting state: fail closed with a typed retryable/rejected reason.
