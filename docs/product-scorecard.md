## Latest tranche

Wave 1, finish loop: workout completion changed from a flat text receipt into an honest full/partial result, scannable retained-work metrics, coaching outcome, next-session handoff and optional privacy-safe share card. Browser verification caught and corrected long-elapsed overflow and pre-existing share-card clipping before commit. No native build is warranted for this tranche.

Wave 1, start flow: Home now labels its planned-session action `Review workout`, matching the destination rather than implying that the session has already started. The workout preview puts the explicit start action directly after the session summary and collapses the six-exercise prescription behind an accessible disclosure. In a seeded 390 × 844 browser journey the start control was fully visible at y=314, prescription review expanded on demand, and the first set became ready 35 ms after start. Starting remains the canonical recording boundary. No native build is warranted for this tranche.

Wave 1, rapid set logging: numeric keyboard completion now performs the action implied by the athlete’s context—confirm the first-exposure load, log the current working set, or save a completed-set edit. The same validation and canonical ledger commands remain authoritative; invalid values still fail safely. In a seeded 390 × 844 browser journey, keyboard submit confirmed calibration in 17 ms, then recorded the set and displayed its persisted 150-second rest state in 24 ms. This removes a separate keyboard-dismiss and small-target acquisition from the highest-frequency logging loop. No native build is warranted for this tranche.

Wave 1, in-workout exercise replacement: the active-workout action is now explicit (`Swap or add exercise`), the editor always offers a return route, and its final confirmation is an in-screen, cross-platform review that states whether only this workout or future sessions will change. A successful current-session replacement returns directly to the exact active workout with history-preservation confirmation styled as success rather than danger. In a seeded 390 × 844 browser journey, Bench Press was reviewed and replaced with the compatible Incline Barbell Bench, the replacement appeared on Train in 275 ms, and the first-exposure calibration boundary remained mounted. Canonical tests still reject changes to an exercise with performed work. No native build is warranted for this tranche.

Wave 1, pause and resume: tapping Home’s `Resume workout` action now performs one identity-and-version-guarded canonical resume instead of reopening a paused screen that asks for a second tap. Manual Resume remains available when a paused workout is opened without explicit resume intent. In a seeded 390 × 844 journey, one performed set and its 2:31 persisted rest state survived minimise-to-Home and returned ready in 197 ms; no duplicate resume control remained. No native build is warranted for this tranche.

Wave 1, focused onboarding: the acquisition journey now offers exactly Hypertrophy, Powerbuilding, and Strength as primary goals, with explicit copy that the adaptive coach is built for muscle, strength, or both. Athletic Performance, Getting Lean, and sport-event programming were removed from active entry points; concurrent sport remains recovery context, and legacy goal types remain readable for retained-data compatibility. All three active 390 × 844 onboarding paths completed successfully into distinct canonical Home programmes (Push hypertrophy A, Push strength and hypertrophy, and Press strength). A five-launch returning-user sample also established that the existing safety-gated local startup is already fast at 350–378 ms (359 ms median), so no speculative startup shortcut was introduced. No native build is warranted for this tranche.

Wave 1, native integration checkpoint: after six connected journey tranches, the Release XCUITest was reconciled to the current product contract and passed end to end on iOS 26.5. It verifies focused onboarding, deterministic 60-minute programme creation, Home review and prescription preview, subscription activation, calibration, working-set logging and editing, workout actions, one-tap guarded resume, keyboard-safe discard, honest early completion, progress/history persistence after relaunch, and duration-change safeguards. The single Release build passed on iPhone 17 Pro, then the same derived build passed again on the narrow iPhone SE simulator at Accessibility Medium text size. No store, signing, upload, build-number, database, Candidate 111, or release state changed; Android native coverage remains unavailable because no Android SDK emulator is installed in this workspace.
