# Compatibility generated-slot prescription seam

D4E3A isolates one generated slot’s prescription mechanics behind a narrow compatibility request. The request contains one exercise, one template slot, the existing compatibility block context and the existing evidence/loading options. The seam calls the unchanged settings, rep, set-prescription and starting-load helpers, then returns the same settings/load result consumed by `createGeneratedSlot`.

This is compatibility infrastructure only. `TrainingBlock` remains temporarily at this boundary; D4E3B removes it after semantic projection and equivalence certification. No current calibration policy, D4D2 runtime path, persistence, formula or generated-workout contract changes here.
